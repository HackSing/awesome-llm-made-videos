# 方法：收录标准、记录单位与证据等级

证据分级和制作路径分类改编自 [athemeroy/awesome-opus-5-5-videos](https://github.com/athemeroy/awesome-opus-5-5-videos) 的方法说明（CC BY 4.0）。本项目在此基础上改了两处：一是按**作品**而不是按**帖子**记录，二是加了一条"转载状态"。

## 收录什么

收录**大语言模型实际参与制作**的视频。模型至少要做了下面其中一件事：

- 写出直接产生画面或声音的代码，例如 Canvas、SVG、WebGL、Three.js、Manim、Remotion、Blender 脚本或 FFmpeg 管线；
- 调度外部工具或外部视频模型，例如负责分镜、提示词和剪辑拼接，并且作者说明了这种分工；
- 对作者提供的现有素材做剪辑或改编；
- 写出一个程序（网页、游戏、模拟器），视频是这个程序的录屏。

**不收**只用文生视频模型（Sora、Veo、Seedance、Kling 等）直接出片、看不到语言模型参与的作品。这类作品已有很多列表在收。

跑分横评、新闻、教程和带货视频不算作品。但它们里面如果展示或转载了别人的作品，就作为这件作品的一条"出现"记录下来，用来追溯来源。

## 记录单位：作品和出现

同一件作品常常在 X、YouTube、B 站、抖音上被多人上传。原仓库以帖子为单位，本项目把它拆成两层：

| 表 | 一行代表 | 关键字段 |
|---|---|---|
| [`data/works.csv`](../data/works.csv) | 一件作品 | 原作者、原发链接、用了哪些模型、主要制作路径、证据等级 |
| [`data/appearances.csv`](../data/appearances.csv) | 作品在某个平台的一次出现 | 平台、链接、上传者、发布时间、时长、抓取时播放量、转载状态 |
| [`data/candidates/<平台>.csv`](../data/candidates/) | 搜索命中、还没人工审过的帖子 | 与 appearances 相同，另有 `review_status` |

候选审过之后，要么拿到一个 `work_id` 进入 appearances，要么标成 `excluded`，并写明原因（评测、新闻、无关、看不出模型参与等）。

## 证据等级

每件作品只标它能达到的**最高**等级，其余证据写在说明里。自动筛选和复核最高只能给到 A\*。A 必须有人核对过：要么是我们在 `data/triage/manual.labels.jsonl` 里手工标注，要么是 athemeroy 人工审核时写明打开了作者的源码并和视频对上（标签里记为 `verified_by: athemeroy`）。

| 等级 | 材料 | 能说明什么 | 不能说明什么 |
|---|---|---|---|
| **A 工程佐证** | 作者公开的代码仓库或工程文件，内容和视频对得上 | 这段画面的生产方式 | 完整的对话过程，也不能外推到别的作者 |
| **A\* 附代码链接** | 帖子附了代码仓库、工程文件或可运行页面，但还没人核对内容和视频对得上 | 作者愿意公开工程 | 这份代码就是生成这段视频的代码 |
| **B 提示词公开** | 作者公开了提示词或详细流程 | 作者给了模型什么输入 | 提示词里写到的每个步骤都真的执行过 |
| **C 作者自述** | 原帖或作者回复里对流程的描述 | 作者自己怎么说 | 这些说法已被独立验证 |
| **D 仅观察** | 平台元数据（时长、发布时间、播放量），以及预览抽帧 | 文件属性和画面内容 | 用了哪个模型、谁做的 |

"一句话生成""零人工修改""跑了 16 小时"这类说法，没有工程或日志佐证的，一律写成"作者称"。

## 三道筛选

| 步骤 | 做什么 | 依据 | 规则 |
|---|---|---|---|
| 初筛 | 判断是不是作品、谁做的、证据等级、是否转载 | 标题、正文、B 站简介 | [`scripts/triage/PROMPT.md`](../scripts/triage/PROMPT.md)，结果在 [`data/triage/`](../data/triage/) |
| 接入 athemeroy 审核 | 他们人工审过的 160 个 X 案例，把审核结论转成本项目的标签 | 作者公开的做法、对方看抽帧写的画面描述、审核结论 | 同上，见其中"athemeroy 人工审核案例"一节 |
| 复核 | 证据在 B 级以上的作品和所有同题对比：写清做法，打开代码链接，B 站作品看预览抽帧 | 正文、代码仓库、B 站预览截图 | [`scripts/review/REVIEW.md`](../scripts/review/REVIEW.md)，结果在 [`data/review/`](../data/review/)，只能下调证据等级 |

athemeroy 的其余 X 候选（九百多条，准确数字见 README 快照）只有对方分类器给的标签，没有帖子正文，本项目没有筛选，也不计入作品，除非有人手工补了标签。

## 转载状态

| 值 | 判定依据 |
|---|---|
| `original` | 已核实上传者就是作者：同名账号互链、作者主页或仓库指向这条，或作者本人在其他平台确认过 |
| `original_claimed` | 上传者用第一人称说是自己做的，但没有交叉核实 |
| `declared_repost` | 上传者自己说明是转载，或在帖子里注明了原作者、原链接 |
| `uncredited_repost` | 能找到更早的原作者，但这条帖子没有注明来源 |
| `suspected_repost` | 没有声明，但有明显的转载迹象（翻译腔标题、描述的是别人的经历、专门的搬运号），还没找到原作 |
| `unknown` | 以上都不符合 |

自动筛选只能给出 `original_claimed`、`declared_repost`、`suspected_repost`、`unknown` 这四种；`original` 和 `uncredited_repost` 需要人工找到原作后，写进 [`data/work_links.csv`](../data/work_links.csv) 并注明依据。

判断转载**不看平台自带的原创标记**。例如 B 站接口的 `copyright` 字段，文档里常见的值是 1（自制）和 2（转载），我们实测还见到了 3；而且这个标记由上传者自己填写。我们原样记录这个值，但不据此下结论。

## 采集

每个平台一个采集脚本，放在 [`scripts/`](../scripts/)，查询词写在 [`scripts/queries.json`](../scripts/queries.json)。每次运行都在 [`data/receipts/`](../data/receipts/) 留下回执，记录每次请求的查询词、排序方式、页码、返回条数和状态。失败的请求也照样记录，不算进覆盖范围。

| 平台 | 方式 | 限速与停止规则 |
|---|---|---|
| B 站 | 匿名公开接口：搜索 + 视频详情 | 请求间隔随机 2–5 秒，每 25 次多停 15–30 秒；遇到风控码（-412/-352/-799/-509）立即停止，不重试 |
| X | 维护者本人的浏览器登录状态，只读人工节奏；只用 Top 排序加日期窗口 | 翻屏间隔 3–8 秒，两次搜索之间 40–120 秒；每轮最多 15 次搜索，每天最多 40 次；遇到限流或验证码就停下，交给人处理。采集时页面必须可见：后台标签页会被限速，只能拿到前 4–8 条，这类回执标为 `degraded` |
| YouTube | YouTube Data API v3 | 受官方每日配额约束 |

所有搜索都有返回上限，还会受到排序、限流、账号可见性和删帖的影响。因此**候选数量不等于平台上的作品总数**，各制作路径的案例数也不代表它们在全平台的真实占比。

## 不分发的内容

仓库里只有链接、公开元数据和我们自己写的说明。视频文件、封面、完整的接口原始返回，以及第三方提示词全文都不进仓库，原始返回只留在本地（`data/raw/`，已加入 gitignore），用于审计。
